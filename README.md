### 6. Теоретичне завдання:  
1. У великих розподілених системах Redis надає корисні механізми, такі як Streams та Pub/Sub. Redis Streams ідеально підходять для обробки потокових даних — журналів подій, метрик або транзакцій. Вони дозволяють групувати споживачів і читати події з певного моменту, що зручно для побудови потокових архітектур. Pub/Sub використовується для миттєвого обміну повідомленнями між компонентами системи — наприклад, для сповіщень чи оновлень у реальному часі.

2. Як брокер повідомлень Redis має свої переваги: це висока швидкість роботи завдяки збереженню даних у пам’яті, простота використання та підтримка реплікації. Проте, є і недоліки — обмеження обсягом оперативної пам’яті та недостатня гнучкість для роботи зі складними структурами даних. Тому Redis добре підходить для простих і швидких задач, але може бути менш ефективним у складних сценаріях.

### Висновки:  

У ході виконання лабораторної роботи було ознайомлено та закріплено знання щодо розширених можливостей Redis. На практиці було використано такі функціонали як транзакції (MULTI, EXEC, WATCH), Lua-скрипти для умовної обробки даних, механізм Pub/Sub для обміну повідомленнями в реальному часі, а також Redis Streams — для роботи з потоковими даними. Усі операції виконувались у середовищі Docker, що забезпечило простоту налаштування та повторюваність результатів.

Redis Streams показали свою ефективність у ситуаціях, де потрібне надійне зберігання подій та підтримка груп споживачів, а Pub/Sub — як простий та швидкий спосіб реалізації взаємодії між модулями системи. Аналіз теоретичних аспектів дозволив визначити сильні сторони Redis — швидкість, простоту і надійність, а також звернути увагу на обмеження, зокрема щодо пам’яті та складних сценаріїв обробки даних. Загалом, Redis є потужним інструментом, який ефективно справляється з багатьма задачами у розподілених системах при правильному підході до його використання.
